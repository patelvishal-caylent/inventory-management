Factory Inventory Management System · Demo

Inventory System Architecture

A four-tier read-only demo: a Vue 3 single-page app talks over plain HTTP to a FastAPI service that filters Python lists held in memory. No database, no ORM, no build step on the server.

System architecture

4 tiers

Each tier below talks only to the one beneath it. The boundary that matters is between tiers 2 and 3: the browser makes a genuine cross-origin request to a separate process, so the app depends on the backend's CORS policy rather than on a dev-server proxy.

In-memory fixtures

server/mock_data.py → server/data/*.json

mock_data.py calls load_json_file() at import time and binds the result to module-level names. Those lists are the database: they live in the uvicorn process, are shared by every request, and reset on restart. Editing a JSON file requires a server restart to take effect.

transactions.json56 finance rows, but keyed to warehouses A/B/C while every other file uses city names.

spending.jsonOne object with three keys, unpacked into three separate names on import.

Six client functions call routes that do not exist

api.js exports getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, pointed at /api/tasks and /api/purchase-orders. The running service publishes 14 paths and neither prefix is among them, so these resolve to 404 — TasksModal.vue cannot load.

Reports.vue bypasses the API client

It imports axios directly and calls http://localhost:8001/api/reports/quarterly and /api/reports/monthly-trends with the host inlined at Reports.vue:156 and :162. It is the only view that does, and the two /api/reports/* routes are the only endpoints api.js does not wrap.

Backlog.vue is orphaned

A finished 152-line view with priority buckets and its own data loading, registered on no route and imported by no component. Backlog data still reaches the UI — Dashboard.vue calls api.getBacklog() directly.

Dashboard renders a component that was never written

<PurchaseOrderModal> appears in the Dashboard template at Dashboard.vue:289 with all its state wired up — showPOModal, poModalMode, openPOModal(), handlePOCreated() — but the component is never imported, never registered, and no such file exists under components/.

Data flow

one filter change, end to end

The filter bar is the spine of the app: four controls at the top of every page feed one shared state object that every view watches. Below is the real path taken when someone changes Location to a single warehouse while on the Overview page — the steps are ordered because each one strictly depends on the last.

The select writes to shared state

components/FilterBar.vue → composables/useFilters.js

FilterBar binds to selectedLocation, a ref declared at module scope in useFilters.js — outside the exported function. Every component that imports the composable receives the same four refs, which is how one dropdown reaches every view without a store or a prop chain.

The active view's watcher fires

views/Dashboard.vue:676

Each view watches all four filter refs as an array and re-runs its loader. Nothing is diffed — any change to any filter triggers a full reload of that view's data.

watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus], () => { loadData() })

Filters are flattened for the wire

useFilters.js — getCurrentFilters()

The UI's vocabulary is translated to the API's here: selectedLocation becomes warehouse, and selectedPeriod is added as month only when it is not 'all'. This rename is the single point where the two naming schemes meet.

Four requests go out in parallel

views/Dashboard.vue:561 — loadData()

The Overview needs four datasets, so it issues them together under Promise.all rather than in sequence. The same filter object is passed to the first three; getBacklog() takes none, because that route accepts no parameters.

const [summary, orders, inventory, backlog] = await Promise.all([ api.getDashboardSummary(filters), api.getOrders(filters), api.getInventory(filters), api.getBacklog() ])

api.js drops the neutral values

client/src/api.js

Each wrapper appends a param only when it is set and not 'all'. The absence of a key is what signals "unfiltered" — so a default page load sends a bare URL with no query string at all.

GET http://localhost:8001/api/dashboard/summary?warehouse=Tokyo

FastAPI filters lists in memory

server/main.py:182

The handler narrows the module-level orders and inventory_items lists through apply_filters() and filter_by_month() — list comprehensions over already-loaded Python objects, so no file is opened and no I/O happens during a request. For warehouse=Tokyo that leaves 88 of 250 orders and 9 of 32 SKUs.

Pydantic validates on the way out — sometimes

response_model=List[InventoryItem] …

/api/inventory, /api/orders, /api/demand and /api/backlog declare response models, so a JSON field that drifts from the model raises server-side. /api/dashboard/summary, the spending routes and the reports routes declare none and return raw dicts — a shape change there surfaces only as a broken chart in the browser.

Raw refs land, computed properties derive

views/Dashboard.vue:573

Responses are assigned to raw refs — summary, allOrders, inventoryItems, allBacklogItems — and loading clears in a finally. Everything shown is a computed over those refs, so the charts redraw from the new arrays with no imperative update.

One panel finishes the job in the browser

views/Dashboard.vue:551

Because /api/backlog takes no parameters, the backlog panel is narrowed client-side: the backlogItems computed builds a Set of SKUs from the already server-filtered inventoryItems and keeps only backlog rows whose item_sku is in it. Filtering is therefore split across the two tiers — by query for orders and inventory, by SKU intersection for backlog.

Inventory has no time dimension

/api/inventory accepts only warehouse and category. Changing the Time Period filter still re-runs loadData() and re-fetches inventory, but the month value is discarded — inventory records carry no date to filter on.

One KPI ignores the filter bar entirely

In the same handler, total_backlog_items is len(backlog_items) against the unfiltered global (main.py:200), so that figure reads 4 no matter which warehouse, category, status or month is selected.

Reports is outside the loop

Reports.vue reads no filter refs and registers no watcher, so steps 1–3 never reach it. The filter bar stays visible above the page but changes nothing on it.

Month matching is a substring test

filter_by_month() checks month in item['order_date'] rather than parsing the date, and QUARTER_MAP hardcodes the four 2025 quarters. Data from another year would pass through the quarter filters unfiltered.
